# Configuration Reference Manual

Persona-Grata composes one agent from a persona, a harness, their dialects, and an optional
password-manager configuration. Configuration is [yapyon](https://pypi.org/project/yapyon/),
requiring yapyon 0.6.5 or newer within the 0.6 series; `.cfg` and `.tmpl` describe the same document format.

## Agent Store

The store root is an explicit `--store DIR`, otherwise `AGENT_STORE_DIR`, otherwise
`$XDG_CONFIG_HOME/agents`, otherwise `~/.config/agents`. Names are registry keys, not directory
names: renaming an agent does not move its files.

```text
~/.config/agents/
  agent_store.cfg
  shared/
    persona/<id>.tmpl
    harness/<id>.tmpl
    dialect/<id>.tmpl
    secret/<id>.tmpl
    agent/<id>.tmpl                 # optional retained source
  entries/<creation-name>/
    agent.cfg
    harness/
```

`--path DIR` can place an agent elsewhere. Registry paths are absolute. There are no name symlinks,
no `__templates__` directory, and no copied library of every bundled preset. Component files are
composed, in-use definitions: missing bundled components are materialized when needed, while
existing stored definitions are reused rather than overwritten by unrelated agent creation.
Edits to stored components affect later resolution. Installed native settings and wrappers are
snapshots regenerated by `--update`; invoking an agent's shell function does not resolve the store.
`paths.shared` and `paths.entries` default to `"shared"` and `"entries"`; relative settings are rooted
at the store, and absolute settings are permitted. Explicit registrations remain authoritative.
Named includes use one shared root everywhere: `secret.pass` selects `shared/secret/pass.tmpl`,
including inside another shared file. Dots become directories, with `.tmpl` at the leaf; one-segment
and deeper labels are permitted. The loaded document supplies its single literal branch value, not
an internal path named by the label. Computed top-level branch keys are refused, not silently dropped. Missing includes fail on reads; only explicit creation/setup provisions presets.

### Bundled Templates

The package catalog uses the same `data/<kind>/<name>.tmpl` naming as shared includes. Each of
`agent`, `persona`, `harness`, `dialect`, and `secret` has `_BUILTIN_.tmpl` and `_DEFAULT_.tmpl`.
`_BUILTIN_` supplies baseline source; `_DEFAULT_` currently forwards to it without config-value
overrides, and concrete presets inherit through `_DEFAULT_`. Those placeholders do not yet implement
the planned template-based config-default wiring. The existing PG defaults binder is described below.

These are ordinary yapyon documents, not extra precedence tiers. Use `:` to combine source values
and `:=` to replace them. The removed bundled `base` labels are not aliases; existing stored source
and shared dependencies are not automatically rewritten or refreshed.

### Store Settings (`<agent-store>/agent_store.cfg`)

This literal root mapping is separate from an agent document. Persona-Grata's packaged
`data/agent_store-defaults.cfg` supplies defaults; `<agent-store>/agent_store.cfg` contains only overrides and
registered agent paths. New nonempty registries include their profile marker. A missing, empty,
or comments-only file uses the defaults. Invalid nonempty content is an error.

```yapyon
format: "agents-yapyon-v0.6.5"
defaults:
  secret:
    backend: "pass"
agents:
  scout:
    path: "/home/you/.config/agents/entries/scout"
env_vars:
  additions: ["MY_ENDPOINT"]
```

| Setting | Type | Meaning |
|---------|------|---------|
| `format` | `str` | `"agents-yapyon-v0.6.5"`; identifies the registry schema |
| `defaults` | mapping | Recursive reusable specification fields in persona, harness, dialect and secret groups |
| `agents` | mapping | Agent name to `{path: "/absolute/directory"}`; default `{}` |
| `paths` | mapping | `shared: "shared"`, `entries: "entries"`; configured store locations |
| `env_vars` | mapping | `from_host` replaces the readable-host-name list; `additions` extends it (default `[]`) |

| Default field | Type | Meaning |
|---------------|------|---------|
| `defaults.secret.backend` | `str` or `None` | Default secret component ID, such as `"pass"`, `"gopass"`, `"prs"`, or a stored custom component; default `None` |
| `defaults.secret.root` | `str` or `None` | Store-relative root for default entry expressions, or `None` for no prefix; default `"agents"` |

Literal registry settings are overlaid field by field for schema records, so changing the root does
not discard the backend. Lists and data-valued settings use the authored whole value. Explicit valid
`None`, empty collections and default-equal values are retained. PG saves explicit settings and agent
records without copying inherited defaults; registry comments and layout are normalized on writes.

The current source-defaults binder accepts reusable fields recursively: persona `mind`, harness
settings, dialect/verification settings and secret locator/operation settings. Entity `name`/`desc`,
`defaults.agent`, `runtime` and unknown specification fields are not eligible. Native `config_store`
and `wrapper_env` are data values, so their data keys are not extra specification fields. The current
binder broadcasts generic dialect defaults into enabled records, below protocol-specific
`defaults.persona.mind.dialects` values; disabled `None` dialects remain disabled. This is adapter
behavior, not an operation supplied by yapyon merging.

Precedence is specification defaults, then store-config defaults, then explicit file settings.
A reused file has no special status. The current binder fills omitted fields while expressions remain
deferred; supplied leaves/lists/native data block those fallbacks. Empty schema records permit
missing-field defaults, while explicit record replacement (`:=`) resets lower defaults. Replacing
that binder with ordinary yapyon defaults/source composition is not implemented yet.

PG still refuses some valid deferred schema-record shapes/computed keys. These are known defects
preventing full core conformance, not permitted format restrictions. Native computed keys and
comprehensions retain ordinary yapyon behavior. All current standard elements and required yapyon
built-ins are core requirements.

The specification supplies omitted model-list/active/subagent fallbacks, fixed harness path,
preferred-first protocol and selected secret root/entry. It does not invent component identities,
endpoints, fetch commands or native output. Other optional fields remain absent unless source/defaults
supply them. Field-section defaults below describe bundled `_BUILTIN_` templates where stated;
those are ordinary file contributions, not a separate implicit defaults tier.

The standard environment allowlist includes `HOME`, `PATH`, `LANG`, and the `XDG_*` directories.
`HOME`, `XDG_CONFIG_HOME`, and `AGENT_STORE_DIR` remain readable for store location regardless of
these lists. Store-only environment policy cannot be overridden by an agent document. Environment values are
available only through permitted yapyon environment references; they are not implicitly expanded
inside plain strings.

## Agent Documents

An installed `<agent-directory>/agent.cfg` has the same partial slot format as an agent preset.
It does not flatten the entire component store or include invocation-owned runtime settings.

```yapyon
agent<agent._DEFAULT_>:
  name: "local_code"
  secret: None
  persona<persona.ollama>:
    mind:
      model_list: ["local-model"]
      model_active: "local-model"
  harness<harness.codex>: {}
```

Names of agents and component IDs use 1–64 ASCII letters, digits, and `_`, and do not begin with a
digit; exact lowercase `default` is reserved. Shell words are valid storage names but cannot be
installed as PG shell functions; use `--no-wrapper`. A persona/harness pair is not a unique agent identifier. Default creation names are
`<persona>_<harness>`; `--name` chooses a different name.

### `agent.format`

String, `"agents-yapyon-v0.6.5"`; supplied by the selected profile if omitted. A present different
marker or computed marker is refused, not rewritten. `agent._BUILTIN_` declares it; `agent._DEFAULT_` inherits it.

### `agent.name`

The registered agent's command name. Renaming changes this name and its wrapper, not its path.

### `agent.desc`

Short description; defaults to `y"{name}"`.

### `agent.persona`

Required persona slot, normally named as `persona<persona.kimi>`. Overrides within the slot are
applied to the selected persona. See [Persona Fields](#persona-fields).

### `agent.harness`

Required harness slot, normally named as `harness<harness.claude>`. One agent has one harness.
See [Harness Fields](#harness-fields).

### `agent.secret`

A secret slot selects the agent's credential backend. It is filled before resolution, so inherited
commands use that agent's final root and entry.

| Form | Meaning |
|------|---------|
| `secret<>: {}` | Use the default backend from `runtime.secret_backend` |
| `secret<>: {entry: "shared/key"}` | Use the default backend with a complete entry override |
| `secret<secret.gopass>: {}` | Select a backend independently of the default |
| `secret: {...}` | Supply a complete inline backend mapping |
| `secret: None` | Explicitly keyless; do not fetch or store a credential |

An entry override is the complete manager entry, without an additional prefix. Two agents can share
credentials by selecting the same backend and entry:

```yapyon
agent<agent._DEFAULT_>:
  name: "scout"
  secret<>:
    entry: "shared/team-key"
  persona<persona.kimi>: {}
  harness<harness.claude>: {}
```

A selected backend can also override the root used by its default entry expression:

```yapyon
agent<agent._DEFAULT_>:
  name: "personal"
  secret<secret.gopass>:
    root: "personal/keys"
  persona<persona.kimi>: {}
  harness<harness.claude>: {}
```

Here the complete entry is `"personal/keys/personal"`, regardless of the agent directory's basename.
A plain mapping is a complete inline backend, not shorthand for overriding only its entry; use
`secret<>` to override fields of the default backend. Inline mappings require `name`, `entry`, and
`fetch` after field-default binding, but do not copy the selected default backend's fields. `store`,
`probe`, and `check` may be omitted, `None` or empty when not provided.

At creation, an unspecified secret keeps the default slot when a backend is configured, otherwise
PG saves `None`. Enabling a default backend later does not silently credential an existing keyless
agent. Agents retaining the default slot follow changes to the default backend; explicit selections
remain independent. An explicit backend does not require a configured default. Overrides on an
anonymous secret slot require a default backend. Use `--no-token` or `secret: None` when no key
should be fetched or stored.

### Runtime-Owned Settings

`runtime.agent_path`, `runtime.defaults`, and `runtime.secret_backend` are supplied by the invocation.
Do not declare them in agent documents or presets. `runtime.defaults` holds the effective store defaults;
`runtime.secret_backend` supplies the default backend for an unspecified agent secret slot, or `{}`
when no default is configured. Credential operations use the resolved `agent.secret`, not this default.

`agent.path` is not a supported field; use `--path` / the registry. Harness paths can refer to
`runtime.agent_path` without storing an installation-specific location in an exported agent document.

## Persona Fields

A component document has a `persona` branch. It may inherit a preset using
`persona<persona._DEFAULT_>`; inside an agent it occupies `agent.persona`.

### `persona.name`

Nonempty persona name. The bundled `_BUILTIN_` placeholder uses `"_DEFAULT_"`; concrete presets
and custom agents supply their own names.

### `persona.desc`

Short description; the bundled `_BUILTIN_` expression is `y"{name} persona"`.

### `persona.mind`

Cognitive configuration mapping.

#### `persona.mind.endpoint`

Required `http://` or `https://` connection endpoint, such as `"http://127.0.0.1:11434"`.
The bundled `_BUILTIN_` template leaves it `None`.

#### `persona.mind.context_size`

Optional positive integer or `None`; booleans are not integers here. `_BUILTIN_` supplies `None`.

#### `persona.mind.model_list`

Ordered list of model IDs; default `[]`. Harness presets may use this to offer model choices.

#### `persona.mind.model_active`

Active model ID; defaults to the first entry in `model_list`, or `None` when the list is empty.
An empty list does not invent a model the server supports.

#### `persona.mind.model_subagent`

Optional subagent model ID; defaults to `model_active`, which may be `None`.

#### `persona.mind.dialects`

Mapping of dialect names to dialect slots. `_BUILTIN_` supplies `chat`, `responses`, and `anthropic`;
this is configuration, not server discovery. Disable an inherited dialect with `:= None`, or override
its mount point:

```yapyon
agent<agent._DEFAULT_>:
  name: "mounted_api"
  secret: None
  persona<persona._DEFAULT_>:
    name: "mounted_api"
    mind:
      endpoint: "https://api.example.org"
      dialects:
        anthropic<dialect.anthropic>:
          api_uri: y"{endpoint}/anthropic"
        responses:= None
  harness<harness.claude>: {}
```

## Harness Fields

A component document has a `harness` branch; inside an agent it occupies `agent.harness`.
Harness-native configuration under `config_store` is free-form data, not extra persona settings.

### `harness.name`

Harness executable / identifier; the `_BUILTIN_` placeholder uses `"builtin_harness"`.

### `harness.desc`

Short description; defaults to `y"{name}"`.

### `harness.path`

Harness configuration directory; `y"{runtime.agent_path}/harness"`. It must stay at that location;
relocate the agent through the registry, not a harness override.

### `harness.auth_var`

Environment variable receiving a fetched token, or `""` when unused; built-in default `"API_KEY"`.
Keyless selection does not clear this or native authentication references: wrapper/inherited external
authentication may still be intended. Selecting a backend does not delete a matching native environment
entry. Optional entries/output filtering belong to the authored harness, not a generic cleanup step.

### `harness.path_var`

Environment variable pointing to the harness configuration directory; default `""`.

### `harness.wrapper_env`

Mapping of valid environment names to string values exported by the shell wrapper; built-in default `{}`.
An explicit empty string is retained, so it can deliberately clear an inherited value.

### `harness.config_file`

Main harness settings filename, relative to `harness.path`; absolute paths, `..` segments and NUL
are refused. `None`, empty or unset means no file is written. Permitted file links retain their
link relationship when written; this is not a new blanket symlink prohibition.

### `harness.config_store`

Native configuration mapping, serialized to `content`; default `{}`. For example, the Codex preset
generates its model table with a dictionary comprehension:

```yapyon
models: {
  model_id: {provider: (persona.name), remote_model_id: (model_id)}
  for model_id in persona.mind.model_list
}
```

The Claude and Codex presets serialize `config_store.__not_none__()`: a recursive copy without `None`-valued
mapping fields or list elements. Codex sets its native `env_key` to `None` when `auth_var` is explicitly
empty, so the output omits the field instead of looking up an empty environment-variable name. The original `config_store` is unchanged. Empty, zero and false values remain.

### `harness.content`

Settings file text, usually built from `config_store` with a serializer; default `""`.

### `harness.supported_dialects`

Required nonempty ordered list, best first. Setup refuses a persona/harness pair with no shared
dialect rather than claiming it is usable.

### `harness.protocol`

Selected dialect name, normally the first enabled dialect in `supported_dialects` order:

```yapyon
protocol: [dialect for dialect in supported_dialects if persona.mind.dialects.__get__(dialect) is not None][0]
```

The required `[0]` fails if no dialect matches. The chosen dialect supplies both API mount points
and verification settings.

## Dialect Fields

A component document has a `dialect` branch; its values are filled into
`agent.persona.mind.dialects.<name>`.

### `dialect.name`

Required nonempty descriptive name; the `_BUILTIN_` placeholder uses `"builtin_dialect"`.

### `dialect.desc`

Optional descriptive string; no implicit value.

### `dialect.api_uri`

Protocol mount point; defaults to `y"{endpoint}"`.

### `dialect.msg_uri`

Completion/message URL. Defaults to `y"{api_uri}/v1/chat/completions"`; the `anthropic` and
`responses` presets select their respective operations.

### `dialect.model_uri`

Model-listing URL; defaults to `y"{api_uri}/v1/models"`.

### `dialect.emb_uri`

Embeddings URL; defaults to `y"{api_uri}/v1/embeddings"`, unset by dialects that do not supply it.

### `dialect.verify`

Optional credential-verification settings for keyed agents. Verification is requested with
`--verify`, not performed implicitly for every setup; requests may incur provider charges.
Warnings can indicate a skipped check, so a successful setup exit is not proof of endpoint or
harness compatibility.

#### `dialect.verify.check_uri`

Verification URL; defaults to `y"{msg_uri}"`.

#### `dialect.verify.key_header`

Authentication-header prefix; default `"Authorization: Bearer"`.

#### `dialect.verify.headers`

Additional header lines; default `[]`.

#### `dialect.verify.body`

Optional request body. Empty means use the installer's minimal probe with the active model.

## Secret Components & Installation

Each agent selects its backend, inheriting the store default unless overridden. Shipped components
include `pass`, `gopass`, and `prs`; stored custom components use the same secret-slot mechanism.
An agent may instead supply a complete inline backend. Guided setup supports the shipped managers;
custom managers must already be configured and initialized.

Installation, preflight, launch wrappers, and `pg --get-secret NAME` use the selected `agent.secret`.
Credential reads and writes go through the manager, not direct `gpg` encryption. Setup assistance may
invoke `gpg` to create a recipient key. Persona-Grata does not create a plaintext token backend or
`.secret_path` pointer.

Creation/update checks the backend and installation targets before saving PG state. Imported credentials
are read back before registration. A late filesystem failure can still leave saved agent source; the
error reports its location, and `--update NAME` retries installation. Credentials are not automatically
deleted after an installation failure.

### `secret.name`

Required nonempty descriptive backend name.

### `secret.desc`

Optional descriptive string; no implicit value.

### `secret.root`

Store-relative root or `None`; defaults to `(runtime.defaults.secret.root)`, normally `"agents"`.
Override it within an agent's secret slot to change that agent's default entry location. `None`
omits the prefix, so the entry is the registered agent name alone; it does not make the agent keyless.
For string roots, leading or trailing `/`, empty path segments, `.` and `..` segments, and leading
`-` are not accepted. An empty string is not a valid root.

This agent uses the `pass` backend with the unprefixed entry `"scout"`:

```yapyon
agent<agent._DEFAULT_>:
  name: "scout"
  secret<secret.pass>:
    root: None
  persona<persona.minimax>: {}
  harness<harness.claude>: {}
```

### `secret.entry`

Complete store-relative manager entry. The base expression is
`y"{root}/{agent.name}" if root is not None else agent.name`; it uses the registered agent name, not
the directory basename. An explicit entry override is used verbatim, without adding the root again.
Unlike the root, the complete entry must always be a nonempty string. Entry paths follow string-root
path rules and cannot contain NUL, carriage returns, or newlines.

Renaming changes a name-derived entry but does not move or rename the password-manager record.
An explicit entry remains fixed across agent renames. Installed wrappers remain snapshots until
regenerated with `--update`.

### `secret.fetch`

Command printing the key to standard output, used during creation/update and by the wrapper at launch.
The manager must be ready for unattended reads; a passphrase prompt can block a launch.

### `secret.store`

Command reading the key from standard input, used when importing a token during creation/update.
`--token FILE` reads a supplied token into the manager; it does not make that file the backend.

### `secret.probe`

Executable required by the backend. Install and initialize your chosen manager separately, or use
`pg --setup` for supported setup assistance. Removing an agent does not delete manager entries.

### `secret.check`

A customized backend may supply an optional `check` readiness command. Commands run as argument
vectors, not through a shell, with output suppressed. Native metadata checks screen supported layouts
but do not prove crypto readiness; unrecognized layouts use strict credential reads rather than treating
errors as missing keys.

## Yapyon Composition & Persistence

- A named slot, `persona<persona.kimi>: {}`, fills a component from a preset. Overrides belong
  inside the slot. Abstract slots such as `persona<>: {}` must be filled before resolution.
- Strings are quoted. `None`, `True`, and `False` are values, not YAML's `null`, `true`, or `false`.
- Ordinary `:` combines compatible containers; `:=` replaces a whole field. In yapyon 0.6.2, a
  higher `None` also replaces an earlier container. Use explicit replacement for complete list changes.
- `y"{reference}"` produces text; `(reference)` copies an entire value, retaining its type.
- `y"{$HOME}/agents"` reads an allowed environment variable; `"$HOME/agents"` is literal text.
- References resolve from their surrounding scope. Use full paths such as `persona.mind.endpoint`
  when crossing component boundaries.
- Claude explicitly calls `y"{config_store.__not_none__().__as_json__()}"`; Codex calls
  `y"{config_store.__not_none__().__as_toml__()}"`. The JSON serializer itself preserves `None` as `null` unless the
  input is explicitly cleaned. TOML omits `None`-valued mapping fields and records their spelling
  under `@_lexemes`. Empty strings, lists and mappings, `0`, and `False` remain.

Composed documents are saved through yapyon's `Tree.to_source()` without resolving remaining slots
or expressions. Comments and layout are normalized; safe merges are compacted, while necessary slot
operations and composition layers remain explicit. Source that cannot be represented faithfully is
refused before an existing output is replaced. The installed agent document remains partial; reloading
uses stored dependencies rather than the changing bundled catalog. PG may faithfully collapse ordinary
base inheritance when provisioning; reads also accept retained agent inheritance under the shared root.

## Migration Boundary

This development version implements candidate `agents-yapyon-v0.6.5`. Older profiles such as `v0.1`
are unsupported, not aliases; a marker edit is not a migration. No existing store is relabeled or
migrated automatically. Preserve old data and migrate only through separately validated operations.

This agent-first format does not read the former persona matrix,
`<old-persona-store>/persona_store.cfg`, or `<old-persona-store>/agent_names.cfg` as a compatibility schema. Recreate agents as single-agent slot documents and
register them by name. `PERSONA_STORE_DIR`, persona-level token paths, `.secret_path`, old designation
selectors, and endpoint/model override flags are not the new store API. Keep old data until you have
confirmed the new agents work; no automatic migration or live harness validation is implied.
